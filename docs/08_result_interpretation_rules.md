# 结果解释规则

## 可支持“完整方法成功”

只有同时满足以下条件：

1. “本地大模型控制器”相对表 A 当前最强合格传统基线“自适应服务器更新”的 station-macro MAE 至少改善 1%，且分层配对 Bootstrap 95% CI 不跨 0；
2. 相对表 B 的“试错控制器”仍有可测增益，才能把收益归因于大模型，而不是一般的自适应控制；
3. worst-station MAE 和 station-CVaR 恶化不超过 0.5%；
4. 在封存确认集上方向一致，并基于冻结协议的 5 种子 validated 主运行和规定压力实验。

## 只允许部分结论的情形

- 主指标显著改善但公平性失败：只声称平均精度改善，并明确公平代价。
- 主指标改善但预算匹配后不显著：不能归因于智能控制，最多归因于额外优化预算。
- 规则控制器或试错控制器与本地大模型控制器相当：不能声称大模型必要；应强调普通控制器的效率。
- 仅特定站点/高污染/压力场景改善：只做该子群或场景结论，标明次要/探索性及 Holm 校正。
- CI 跨 0：报告无充分证据，不把均值方向写成“优于”。
- 结果为负：工程仍可完成，论文以边界条件、失败模式或负结果呈现。

## 禁止解释

- 用最佳种子、最佳站点或最佳轮替代预注册汇总。
- 用测试集选择模型、Prompt、规则阈值、压力强度或剔除异常运行。
- 将客户端间模型参数通信表述为已证明隐私安全。
- 从单城市历史数据推出普遍空气质量部署结论。
- 将模拟掉线/漂移等同于真实世界全部故障。
- 对 invalid、缺文件、哈希不匹配或客户端不齐的运行报告性能。

## 报告最小集合

每张主结果表需给出方法、种子数、mean±std、绝对/相对差、95% CI、效应方向、运行 ID 集合。正文同时给宏/微误差、最差站、公平性、高污染、资源和 LLM 成本；附录保留逐站点结果、失败运行与限制。

## 审计优先级

出现数字冲突时，以逐样本 predictions 重算值为准，其次是 validated summary，再次是自动报告；手写表格不作为证据。修正数字必须更新生成脚本并重新构建，不能只改论文文字。
