# 实验对比规范与方法名称目录

状态：`v2_display_and_comparison_contract`（2026-08-18）。

本文件解决两个容易混淆的问题：

1. 代码里的 `pafa_*` 是运行 ID，不是论文里的算法名称；
2. 联邦优化、客户端控制器、隐私传输协议和持续学习基线属于不同层次，不能直接混成一张“谁最好”的表。

代码 ID 保持不变，报告和论文统一使用本文件的显示名。生成报告时，`Comparison group`、`Layer`、`Method` 和 `Internal ID` 四列会同时出现，既方便阅读，也能回到原始工件。

## 1. 先看哪一张表

| 表 | 比较对象 | 主要问题 | 是否可以直接互相排名 |
|---|---|---|---|
| 表 A：传统联邦主表 | 平均聚合、稳定本地训练、自适应服务器更新、完整方法 | 完整方法是否超过强的传统联邦优化 | 可以；但必须同一数据、模型、轮数、客户端和评估协议 |
| 表 B：控制器公平对比 | 预算匹配稳定本地训练、规则控制器、试错控制器、本地大模型控制器 | 收益来自哪一种客户端决策器，尤其是大模型是否比普通控制器更有价值 | 可以；这些方法共享状态、动作、探针和预算合同 |
| 表 C：机制消融 | 完整方法、无探针、无群组协调、无私有记忆等 | 哪个模块真正起作用 | 只在同一方法内部解释，不与传统基线混排 |
| 表 D：持续学习参照 | Naive、Replay、KD/LwF、EWC、Online-EWC、SI 等 | 是否减少连续任务中的遗忘 | 只能在同一持续任务协议下比较，不能把 AF/AP 数字和表 A/B 的一步预测 MAE 混在一起 |

### 结论读取顺序

先看表 A，判断完整方法相对强传统联邦方法是否有总体收益；再看表 B，判断收益是否确实来自客户端控制器、是否超过同动作空间的试错控制器；最后看表 C，解释机制。表 D 是独立的持续学习证据，不替代表 A 的精度结论。

## 2. 论文显示名与代码 ID

### 2.1 传统联邦参考

| 论文显示名 | 代码 ID | 直白含义 | 当前资格 |
|---|---|---|---|
| 平均聚合（FedAvg） | `pafa_fedavg` | 每个站点的模型更新做等权平均 | 当前主表基线 |
| 稳定本地训练（FedProx） | `pafa_fedprox` | 本地训练不要离全局模型太远，减少站点差异带来的震荡 | 当前主表基线 |
| 自适应服务器更新（FedAdam） | `pafa_fedadam` | 服务器根据历史聚合结果自动调整更新方向和幅度 | 当前最强传统开发基线 |
| 公平性加权聚合 | `qfedavg` | 让误差较大的站点在聚合中得到更多关注 | 当前未接入 Secure Aggregation（安全聚合），适配前不进正式主表 |

`fedavg`、`fedprox`、`fedadam` 是普通参考实现；对应的 `pafa_*` 是当前通过 Secure Aggregation（安全聚合）工程门禁的运行版本。算法名称相同，结果可以按同一算法解释；但如果比较隐私协议，必须单独标注两者的传输条件，不能把普通参考实现写成使用了安全聚合。

### 2.2 客户端控制器对比

| 论文显示名 | 代码 ID | 直白含义 | 在哪张表 |
|---|---|---|---|
| 预算匹配的稳定本地训练 | `pafa_fedprox_budget_matched` | 不做智能选择，但花掉与控制器相同的探针预算，排除“计算更多”造成的假提升 | 表 B，核心控制组 |
| 规则控制器 | `pafa_rule` | 按固定人工规则选动作 | 表 B，非大模型控制器 |
| 试错控制器 | `pafa_bandit` | 根据过去动作的结果逐步选择更可能有效的动作 | 表 B，最重要的非大模型近邻 |
| 本地大模型控制器 | `pafa_llm` | 大模型只在站点本地看私有状态并提出候选动作 | 表 A/B，完整方法候选 |
| 本地大模型控制器（无探针） | `pafa_llm_no_probe` | 去掉局部试跑，检验探针是不是必要 | 表 C，消融 |
| 探针上界控制器 | `pafa_probe_oracle` | 用探针结果做近似“事后最优”选择，估计动作空间的上限 | 表 C，机制上界 |

这些控制器都使用同一套 Secure Aggregation（安全聚合）运行条件，服务器只看到群组摘要；站点的残差、漂移、详细探针和智能体记忆留在本地。这里的“群组协调”是本项目对聚合摘要和公共 `CohortDirective` 的描述，不是联邦学习的标准术语，也不把它当成联邦学习天然拥有的额外隐私保证。

## 3. 具体的比较关系

### 表 A：传统联邦主表

固定行：

1. 平均聚合（`pafa_fedavg`）；
2. 稳定本地训练（`pafa_fedprox`）；
3. 自适应服务器更新（`pafa_fedadam`）；
4. 本地大模型控制器（`pafa_llm`）。

表 A 回答：在相同模型、数据、12 个客户端、通信轮数和基本本地训练预算下，完整方法是否超过最强传统联邦方法。主差异优先报告 `pafa_llm - pafa_fedadam`；如果加入预算匹配控制，则同时报告 `pafa_llm - pafa_fedprox_budget_matched`。

### 表 B：控制器公平对比

固定行：

1. 预算匹配的稳定本地训练（`pafa_fedprox_budget_matched`）；
2. 规则控制器（`pafa_rule`）；
3. 试错控制器（`pafa_bandit`）；
4. 本地大模型控制器（`pafa_llm`）。

四行必须共享：状态字段、候选动作、探针次数、每轮本地训练步数、公共指令、客户端集合和种子。这里的主问题是：

- 控制器是否比不做自适应的预算匹配控制更好；
- 大模型是否比同动作空间的试错控制器更好；
- 如果大模型没有额外收益，就不能把规则或试错控制器的收益写成“大模型带来的收益”。

探针上界（`pafa_probe_oracle`）不作为普通竞争方法，而是用来判断当前动作空间本身还有多少可利用空间。

### 表 C：机制消融

| 完整版本 | 对照版本 | 只回答什么 |
|---|---|---|
| 本地大模型控制器 | 本地大模型控制器（无探针） | 探针是否减少错误动作 |
| 本地大模型控制器 | 无群组协调反馈 | 公共协调是否真的改变本地决策 |
| 本地大模型控制器 | 无私有记忆 | 跨轮记忆是否有用 |
| 本地大模型控制器 | 无尾部风险目标 | 尾部站点改善是否来自风险目标 |
| 本地大模型控制器 | 预算匹配的稳定本地训练 | 整个控制闭环是否值得额外复杂度 |

尚未实现或尚未通过门禁的消融保持 `TBD`，不得用推测填表。

### 表 D：持续学习独立表

参考论文中的 Naive、Replay、KD/LwF、Online-EWC、EWC、SI 等方法必须使用相同的任务边界、模型、预测步数和 AF/AP/AvgPerf 定义。当前项目的持续学习 Secure Aggregation（安全聚合）适配已经完成工程 smoke，但尚未完成同条件正式复现实验，因此表 D 目前只登记方法和协议，不提供跨表胜负结论。

## 4. 当前开发结果如何读

`docs/p2_secure_baseline_screening_20260818.md` 中的单种子结果只用于开发筛选，不是正式论文表。当前结果应按下面方式描述：

- 自适应服务器更新（`pafa_fedadam`）是当前平均 MAE 最强的传统基线；
- 试错控制器和规则控制器属于表 B 的控制器对照，不能直接说它们“超过了大模型”，因为真实本地大模型性能尚未完成；
- 探针上界的高污染站点指标最好，说明风险敏感/尾部公平可能是更有希望的结论方向，但不能因此声称总体精度胜出；
- 所有数值都标为 validation-only、single-seed development，正式 test、多种子和封存确认集仍受门禁约束。

## 5. 明确禁止的比较

- 不把 `pafa_fedadam`、`pafa_bandit`、`pafa_llm` 和持续学习的 AF/AP/AvgPerf 放到同一张表里；
- 不把 `fedprox` 的非安全结果当成 `pafa_fedprox` 的安全结果；
- 不把旧版 `mas_llm` 与 v2 `pafa_llm` 直接混为同一个方法；
- 不把参考论文在不同模型、目标变量或任务边界下报告的数值直接与本项目 MAE 排名；
- 不把协议不兼容的客户端选择/加权方法静默改写后称为同条件基线；
- 不把“Secure Aggregation（安全聚合）群组协调”写成联邦学习天然具有的标准模块，安全边界只归因于实际启用并验证的安全聚合协议。

## 6. 报告列的固定顺序

所有自动生成的结果表固定使用：

`Comparison group` → `Layer` → `Method` → `Internal ID` → `Seed` → `Macro MAE` → `Worst Station MAE` → `Station MAE CV` → `Status`。

缺失值写 `TBD`。任何方法若未在本目录登记，报告显示“未分类（需登记）”，不得直接进入主表。
