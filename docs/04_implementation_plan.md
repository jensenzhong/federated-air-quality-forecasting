# 实施计划与门禁

## 工作分解

| 阶段 | 输入 | 实施 | 输出 | 门禁 |
|---|---|---|---|---|
| M0 | 旧项目 | 哈希、归档、精确删除、脱敏 | 旧项目归档与删除清单 | 密钥扫描 0 命中；目标 CSV 不存在 |

## 配置与变更流程

1. 提案写入 `07_decision_log.md`，说明问题、候选方案、影响与回滚方式。
2. 对影响数据/模型/指标/统计的变更创建新配置或新运行 ID，不修改旧运行。
3. 先补测试，再实现；通过阶段检查后更新 `PROJECT_STATUS.md` 与 `ccfa.yaml`。
4. 协议冻结后，仅允许修复明确实现错误；任何实质方法变化视为新实验族。

## 完成定义

每项实现需同时满足：代码存在、配置可解析、测试覆盖关键边界、真实命令可执行、产物字段齐全、文档与代码一致。只完成代码而未取得阶段门禁证据时状态保持“进行中”。

## 资源和预计时长治理

先测 1 轮峰值内存，再测 3 轮稳定时长。记录 CPU、可用内存、每客户端耗时与字节量。不得通过降低客户端数伪装主实验成功；若资源不够，保留可运行工程并将 M4/M6 标记阻塞。

## 交付顺序

安全和数据正确性优先于模型性能；基线优先于复杂方法；Rule-MAS 优先于 LLM-MAS；单种子正确性优先于多种子队列；validated 结果优先于报告排版。
