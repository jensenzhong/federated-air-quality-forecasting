# LLM-MAS v2 隐私威胁模型与联邦边界

状态：`mandatory_gate`。任何与本文件不一致的 PAFA/LLM-MAS 运行均无实验资格。

## 1. 核心边界

联邦学习是主体：原始数据、逐样本预测、残差序列、时间戳和本地诊断记忆始终留在客户端。LLM 智能体只能改变客户端本地训练行为或根据安全聚合后的群组信息协调联邦过程，不能建立中心化数据副本。

“数据没有集中上传”不等于“已经证明隐私安全”。模型更新和客户端统计仍可能泄露成员、属性或输入信息。因此正式方法至少需要安全聚合；若声称形式化隐私，还需要明确的 DP 邻接定义、裁剪、噪声机制和隐私会计。

## 2. 威胁主体

- 诚实但好奇的聚合服务器：按协议运行，但尝试从单个更新或指标推断站点数据。
- 外部 LLM 服务商：所有发送到其 API 的提示都视为离开联邦信任域。
- 被攻陷的客户端：尝试通过恶意更新、诊断文本或协作消息获取其他客户端信息。
- 日志/工件读取者：可能通过 client ID、逐轮指标或时间轨迹重新识别站点。

当前不声称抵御服务器与足够多客户端串谋、端点操作系统被完全攻陷或训练后模型的所有未知攻击。

## 3. 允许的数据流

### 客户端内部

- 原始时序、标签、逐样本残差；
- 私有状态胶囊与跨轮记忆；
- 本地 LLM 站点智能体的提示和响应；
- 候选动作影子试验及其详细结果。

客户端 LLM 必须运行在回环地址或组织控制的本地端点。默认 DeepSeek 公网端点不得接收这些内容。

### 客户端到服务器

- 通过 SecAgg+ 遮蔽的加权完整模型参数；
- 通过安全聚合得到的群组计数、总和或裁剪直方图；
- 达到 `coordinator_min_cohort_size` 后才能释放的聚合摘要。

正式协议禁止服务器读取单客户端模型更新、MAE、漂移分数、诊断、探针收益、动作历史和持久标识。

Flower 1.22 的具体数值路径是：先以 `num_examples / max_weight` 乘以客户端返回的完整模型参数，再对每个坐标裁剪到 `[-clipping_range, clipping_range]`，随后量化和加掩码。当前 PAFA 固定 `num_examples=max_weight=1` 以实现站点等权。客户端本地可以先缩放 `local_model - global_model` 的贡献，但送入 Flower 的仍是缩放后的完整模型参数；这不是更新差分的 L2 范数裁剪，也不构成 DP 机制。

### 协调 LLM

协调智能体只接收群组级、裁剪/量化后的摘要，例如全局验证趋势、动作类别总数、总计算预算和聚合后漂移直方图。提示不得包含站点名称、client ID 或可链接的单客户端轨迹。

## 4. 禁止的数据流

- 原始行、窗口、标签、时间戳、预测或残差序列进入服务器或任意云 LLM；
- 将 12 个站点的逐客户端状态拼接进服务器端 LLM prompt；
- 在日志中保存客户端私有提示、详细 probe 结果或稳定真实身份；
- 为了客户端级动态权重而让服务器检查单客户端更新方向；
- 将 TLS 误写成安全聚合，或将安全聚合误写成差分隐私。

## 5. 隐私兼容的多智能体协同

1. 每个站点的本地 LLM 智能体读取私有状态并提出本地训练动作。
2. 本地验证器用影子试验验证动作；详细证据不离开客户端。
3. 客户端先在本地形成受约束的完整模型参数；Flower 对其加权后逐坐标量化裁剪并加掩码，通过 SecAgg+ 上传。
4. 服务器只能取得聚合模型与达到群组阈值的摘要。
5. 全局协调 LLM 根据聚合摘要生成下一轮公共目标、预算上限和动作约束。
6. 公共指令广播到客户端；客户端智能体结合本地状态自主执行。

该设计仍属于联邦学习：模型在本地训练、服务器只聚合更新；智能体负责协议内协同，不接管或集中原始数据。

## 6. 工程门禁

- 旧 `AgenticAggregationStrategy` 会接收逐客户端回复，构造时现已直接报错；服务器端 PAFA proposer 路径已从 `ServerApp` 删除。
- PAFA 训练使用 Flower 1.22 的 `SecAggPlusWorkflow + secaggplus_mod`。合成 3 客户端四阶段工作流已验证；客户端 mod 仅在真实 `COLLECT_MASKED_VECTORS` 调用期间打开私有门禁，在上传前删除应用指标并把明文样本数替换为常数 1。伪造 `fitins.parameters` 而缺少 SecAgg+ 协议记录的请求会在本地训练前被拒绝。
- 模型参数与固定长度群组统计向量在同一次 SecAgg+ 中求站点宏平均；聚合协调器只读取解密后的群组向量。系统传输层仍需使用 node ID 路由密码学消息，但该标识不进入协调器或 PAFA 工件。
- 当前工程语义要求 setup、share keys、collect masked vectors、unmask 四个阶段都覆盖完整唯一客户端集合，且每个成员恰好回复一次。任何缺失、重复、失败或集合不一致均使该轮 fail-closed，不进入协调器或有效检查点；当前不主张已验证掉线容错。
- 每个客户端 SecAgg+ 会话绑定 `run_id`、本地 `node_id`、数值轮次 `group_id` 与严格阶段顺序；collect 额外绑定 `method` 和 `server-round`。聚合端拒绝轮次重放/跳跃以及重复或不完整代理身份。
- 数值预检要求有限正 `clipping_range`、int32 安全的量化范围、2 的幂模数、足够容纳群组求和的模数容量，并固定 `max_weight=1`。客户端只把“完整模型参数可能被逐坐标裁剪”的布尔量放入安全聚合摘要；聚合指示一旦代表至少一个客户端违规，本轮在协调器观察和工件落盘前失效。
- 当前只具备 nonformal 验证集工程运行资格。`evaluation_split=test` 继续 fail-closed；`protocol_frozen=true` 还要求机构隔离 ClientApp，进程内顺序 runner 不具备正式资格。
- 顺序 runner 对 partition 和站点配置的唯一完整性检查，以及 Flower 消息的 run/source/destination/group/type/reply-to 校验，只是工程身份门禁。正式部署仍缺少由机构签名或等价可信注册机制建立的 `Flower node -> physical station` 绑定；在此之前不能声称已验证真实站点成员身份。
- 同进程 smoke 只能证明协议调用、数据最小化与聚合闭环；由于服务器和客户端共享进程、主机及信任域，它不能证明网络攻击面隔离、机构隔离或正式隐私安全。
- `privacy.differential_privacy_enabled=false` 时只能主张数据最小化与安全聚合边界，不能主张 DP。
- 实验研究者离线查看 per-station 指标必须与在线算法输入严格分离，并在论文中说明这是评估权限，不是生产服务器权限。

## 7. 安全测试状态

- `passed`：Flower SecAgg+ setup/share/collect/unmask 合成闭环；只恢复群组模型和群组统计均值。
- `passed`：少于最小群组规模拒绝释放摘要；缺少 SecAgg+ 协议记录的 PAFA 请求和公网客户端级 LLM 端点 fail-closed；旧外部端点开关不能绕过策略；原始/时间戳/残差/test prompt 字段拒绝。
- `passed`：PAFA 服务端事件和顺序资源日志不含 client/node/station 标识；`client_metrics.parquet` 必须为空。
- `passed`：四阶段严格全客户端、缺失/重复、会话重放/乱序、消息身份与轮次绑定、数值容量、聚合裁剪指示及 12 客户端合成量化误差回归已通过 2026-08-18 全量验证（`105 passed, 1 skipped`；ruff、mypy、diff 检查通过）。
- `pending`：12 站真实 ClientApp 消息扫描和 P1 同进程 smoke；结果只能作为 nonformal 工程证据。
- `pending`：安全聚合 test 指标协议、机构隔离部署，以及机构签名的 `Flower node -> physical station` 绑定验证。
- `not_applicable`：DP 尚未启用；没有隐私会计或 DP 主张。
